# Share a file with the intended audience

Identify the exact file and workspace, the intended recipients and whether they need to read, comment, edit or download. Resolve similarly named files before changing access.

Inspect ownership and existing direct or inherited permissions. A copied restricted document link does not grant access. For colleagues, prefer the appropriate direct role. For an external link, check that the owner and workspace permit it, and choose the requested expiry and download behaviour.

Create, revoke or modify access only within the user's request. Do not enable external sharing for an entire workspace to solve one file problem without authorisation. A file-share URL can expose its content; treat the URL itself as private when appropriate.

Verify the resulting permission list or link state. Where feasible, test the recipient experience with an authorised test account or signed-out view without exposing content publicly. Check scan readiness before concluding that a download is broken.

Return the intended link only to the intended audience, the access role, expiry and observed result. Revoke an incorrect new grant promptly when recovery is authorised, and verify that inherited access has also been considered.
