# Configure a focused voice agent

Establish the agent's role, audience, call direction, source of approved answers and desired outcome. Confirm the intended organisation and whether configuration changes and test calls are authorised. Use the actual available dashboard or connector fields rather than inventing API endpoints.

Specify an opening, tone, questions, completion condition and human handoff. Identify what the agent must do when it does not know an answer. Do not promise a refund, price, appointment or other commitment that its tools cannot verify.

Attach the intended knowledge base and wait for source processing to be ready. Enable only the tools needed for the workflow. Check model, voice, language and time zone against the scenario; save changes using the product's supported flow.

Start with browser testing where available. With permission, call a test number controlled by the user. Check interruptions, corrections, unknown questions, callback requests and escalation. Review disclosure and recording settings without asserting legal compliance.

Verify downstream SMS, calendar or CRM results separately from the agent's spoken claim. Do not buy a number, start a paid call or launch a wider campaign just because the agent configuration is ready. Return configuration changes, test observations and the next required production step.
